# Content Factory V2.7 — Operator Production Console

## Purpose

The local Dashboard is the primary interface for normal content production. An operator selects a canonical brand, chooses `FAST` or `QUALITY`, enters a creative brief, runs a zero-generation preflight, explicitly starts production, follows durable progress, previews the immutable master, and approves, rejects, retries, or regenerates it.

The terminal remains available for development, migrations, diagnostics, recovery, CI, and infrastructure. The HTTP API does not execute CLI commands.

## Architecture

```text
Browser
  ↓
Control API
  ↓
ProductionCommandService
  ↓
Existing LiveProductionService / Factory Engine
  ↓
RendererRouter
  ├── FAST → MoneyPrinterTurbo
  └── QUALITY → V2.5 durable media + FFmpeg
  ↓
Immutable artifact + validation
  ↓
Human Review Queue
```

Both the production CLI and Dashboard use `src/v2.7/production-runtime.js` for the same V2.5/V2.6 renderer and provider wiring. The Dashboard never shells out to `real:production` or `live:production`.

## Starting locally

Prepare the existing V2.1–V2.6 development schema and artifact directory first. V2.7 adds no migration.

Safe preflight-only Dashboard:

```bash
LIVE_PAID_GENERATION=false npm run dashboard:local
```

Open `http://127.0.0.1:3000`. Both servers bind to localhost by default.

Provider/renderer configuration is observational and credentials are never returned to the browser. `QUALITY` requires the existing Replicate video and OpenAI speech configuration. `FAST` requires:

```text
FAST_RENDERER=moneyprinterturbo
MPT_ENABLED=true
MPT_BASE_URL=http://127.0.0.1:8080
MPT_AUTO_PUBLISH_DISABLED=true
```

`MPT_AUTO_PUBLISH_DISABLED=true` is mandatory. FAST never silently falls back to QUALITY, and QUALITY never silently falls back to FAST.

## Creating a production

1. Open **New Production**.
2. Select an active canonical brand.
3. Choose `FAST` or `QUALITY`. An unavailable lane is disabled with a reason.
4. Enter a title, objective, platform, duration, hook, core message, creative brief, and CTA.
5. Optionally open **Advanced** for voiceover, scene ideas, visual direction, captions, music intent, audience, campaign, or additional instructions.
6. Select **PREPARE / PREFLIGHT**.
7. Review the renderer, generation count, external execution count, unknown/known cost, publication policy, and schema status.
8. Select **START PRODUCTION** only when ready to cross the displayed external-cost boundary.

The backend constructs the V2.6 canonical production input. The operator brief remains authoritative. Available Brand Brain information is reference context and does not overwrite explicit instructions.

## Preflight

Preflight always forces a plan-only runtime even when the Dashboard process is configured for live execution. It validates canonical input, ownership, schema, storage, durable execution claims, and renderer capability.

Hard guarantees:

```text
preflightProviderExecutions = 0
dryRunProviderCalls = 0
dryRunRendererExecutions = 0
```

A MoneyPrinterTurbo health GET may inspect service availability when enabled; it cannot create a render job. Preflight never creates or starts the production.

## Starting production

Start is a separate API command with an explicit confirmation. The server first creates one durable `DRAFT` production and `QUEUED` job, keyed by the operator request UUID and canonical fingerprint. Repeated browser submissions converge on the same rows. The existing PostgreSQL job claim prevents two workers from crossing the same external boundary.

Closing or refreshing the browser does not cancel the server-side task. The UI reloads production, job, execution, artifact, validation, and review truth from PostgreSQL.

To allow a controlled real Start, restart the Dashboard with the existing live gate and valid provider configuration:

```bash
LIVE_PAID_GENERATION=true npm run dashboard:local
```

Starting the Dashboard makes no generation call. Only the explicit **START PRODUCTION** action can enter the existing paid/external renderer path.

## Retry

**Retry same execution** continues the same intended production after a retryable technical failure. It reuses the canonical production identity and durable provider/renderer execution records. Completed work is not rerun. Ambiguous `MAY_HAVE_STARTED` or `NEEDS_RECONCILIATION` state fails closed and must be handled with existing recovery tooling.

## Regenerate

**Regenerate new revision** creates a new `DRAFT` production with a new operator request identity and `regeneration_of` provenance. It does not start automatically. The operator must explicitly start the new production.

Regeneration never overwrites the previous master, validation, review item, or decision. A new master requires its own validation and human review. Regeneration is unavailable while the previous execution is queued, running, or ambiguous.

## Review

The Review Queue shows the exact immutable master, duration, codecs, validation evidence, generated assets, renderer/provider provenance, and publication state. `APPROVE` and `REJECT` preserve the existing V2.3/V2.5 durable review semantics.

```text
APPROVE != PUBLISH
```

## Publication

Every operator production is created with:

```json
{
  "requiresHumanApproval": true,
  "autoPublish": false
}
```

Approval and regeneration never invoke publication. V2.7 contains no auto-publish control and no social publishing integration.

## Recovery

The production detail page derives status from persisted production, job, provider/renderer execution, validation, and review state. Safe error details are shown without credentials. Retry is enabled only for `RETRYING`. Regenerate is disabled while execution is active or requires reconciliation.

Developer recovery, reconciliation, migrations, and incident diagnostics remain CLI responsibilities.

## Local certification

No test command performs a real provider generation:

```bash
npm run test:v2.7
npm run test:v2.6
npm run test:v2.5
npm run test:v2.4:live-production
npm run test:v2.3:control
npm run test:v2.3:client
npm run dashboard:build
```

V2.7 tests exercise Dashboard/API input, preflight, idempotent creation, explicit start, FAST/QUALITY routing through mocked runtime lanes, retry safety, immutable regeneration, Review Queue behavior, and refresh from backend truth. Provider invocations in those tests are in-process mocks only.

The deterministic PostgreSQL end-to-end path is deliberately guarded against `content_os`. Create a disposable database, then run:

```bash
createdb content_factory_v27_test
CONTENT_FACTORY_TEST_DATABASE=1 \
PGDATABASE=content_factory_v27_test \
npm run test:v2.7:postgres
dropdb content_factory_v27_test
```

The test bootstraps and removes only the disposable database schemas. Its renderer is a deterministic local fixture and its real provider call count is zero.

## Controlled real certification

After mocked/local certification is green:

1. Start MoneyPrinterTurbo locally with cross-post/upload disabled.
2. Start the Dashboard with `LIVE_PAID_GENERATION=true` and the existing FAST variables above.
3. Open **New Production**, select **Attune**, and choose **FAST**.
4. Enter a short creative brief and run preflight.
5. Verify renderer availability, expected external executions, `Estimated cost: UNKNOWN`, human approval required, and auto publish `NO`.
6. Explicitly start one production.
7. Wait for the immutable master, validation `PASS`, and Review Queue item.
8. Review the exact master and approve or reject it. Confirm publication remains not triggered.
9. Separately repeat with `QUALITY` only after reviewing the reported paid call count and current provider pricing.

Implementation and CI do not execute this real procedure automatically.

## Limitations

- Local/private interface only; remote authentication and deployment are out of scope.
- The simple form creates deterministic approximately five-second visual beats for QUALITY; it is not a shot timeline editor.
- Cost remains `UNKNOWN` when the underlying provider/renderer contract does not return a verified amount. FAST is not labelled free.
- QUALITY captions remain disabled because the current FFmpeg master does not burn them. FAST captions are offered only because MoneyPrinterTurbo renders them.
- Browser closure is safe, but stopping the Dashboard server process may require normal durable retry/reconciliation tooling.
- Regeneration is whole-production only and is available for productions created through the V2.7 operator command boundary; certified historical productions remain immutable and are not silently converted.
- Publication, analytics, collaboration, billing, key editing, and autonomous production are not included.
