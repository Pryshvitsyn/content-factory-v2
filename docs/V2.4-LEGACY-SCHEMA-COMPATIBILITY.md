# V2.4 Legacy Schema Compatibility

## Root cause and ownership decision

The local Content OS database contains early V2.1 tables whose names overlap the certified execution tables but whose columns, checks, indexes and function return types differ. `CREATE TABLE IF NOT EXISTS` does not upgrade such tables. Historical migrations therefore appeared to succeed until a specific write reached the first incompatible element.

The canonical brand authority for V2.2, V2.3 and V2.4 is `v2_2.brands(id)`. `v2_1.productions.brand_id` must reference that identity. A legacy FK to `v2_1.brands(id)` is invalid for current production ownership and is replaced, never disabled.

Existing legacy productions can reference brand IDs that cannot be mapped to a persisted workspace. They are not rewritten or assigned fabricated brands. The canonical FK is installed `NOT VALID`: PostgreSQL enforces it for every new/changed brand reference, while untouched historical rows remain queryable. It is validated automatically only when every persisted production brand already exists in `v2_2.brands`.

`public.brands` rows may be copied to `v2_2.brands` only with the exact existing `id`, `workspace_id` and `name`. Conflicts or missing workspace ownership fail closed. `v2_1.brands` rows are not copied because that schema does not prove workspace ownership.

## Canonical table contracts

`NOT NULL` below describes the clean canonical schema. An upgraded legacy database may retain nullable columns where historical rows cannot be repaired semantically. V2.4 supplies every such value and proves the write in a rolled-back transaction before a provider call.

### `v2_1.productions`

- Required: `id uuid`, `workspace_id uuid`, `brand_id uuid`, `name text`, `status text`, `created_at`, `updated_at`, `metadata jsonb`.
- Optional: `objective text`, `started_at`, `completed_at` and V2.2 growth references.
- Defaults: UUID, `DRAFT`, timestamps, `{}` metadata.
- Unique: `(workspace_id,name)`; index `brand_id,created_at`.
- FKs: `workspace_id → public.workspaces(id)`; canonical `brand_id → v2_2.brands(id)`.
- Status: `DRAFT|RUNNING|COMPLETED|FAILED|CANCELLED`.

### `v2_1.jobs`

- Required: `id`, `production_id`, `stage`, `status`, `attempt`, `max_attempts`, `idempotency_key`, `payload`, `result`, `error`, `created_at`, `updated_at`.
- Lease fields: `worker_id`, `lease_expires_at`, `heartbeat_at`, `next_attempt_at`; optional `generation_job_id`, timestamps.
- Defaults: UUID, `QUEUED`, attempt values, JSON objects and timestamps.
- Unique: `(production_id,idempotency_key)`; claim index on status/next attempt/lease/creation.
- FK: `production_id → v2_1.productions(id)`.
- Status: `QUEUED|RUNNING|COMPLETED|FAILED|CANCELLED|RETRYING|DEAD_LETTER`.

### `v2_1.stage_runs`

- Required: `id`, `job_id`, `stage`, `attempt`, `status`, artifact arrays, `max_attempts`, `error`, `metadata`, `created_at`, `updated_at`.
- Optional: worker/lease/timestamps/fingerprints/next attempt.
- Defaults: UUID, attempt values, `PENDING`, empty JSON arrays/objects and timestamps.
- Unique: `(job_id,stage,attempt)`; claim index on job/status/next attempt/creation.
- FK: `job_id → v2_1.jobs(id)`.
- Canonical status: `PENDING|RUNNING|COMPLETED|FAILED|RETRYING|DEAD_LETTER|SKIPPED`. The compatibility check also preserves legacy `QUEUED|CANCELLED` rows.

### `v2_1.asset_registry`

- Required: `id`, `asset_id`, `kind`, `semantic_key`, `artifact_storage_key`, positive `artifact_version`, `status`, `metadata`, `created_by`, timestamps.
- `production_id` is supported for reusable/global legacy assets but every V2.4 production asset supplies it.
- Defaults: UUID, `READY`, `{}` and timestamps.
- Unique: `(production_id,asset_id)`; reuse index on asset/kind/status/creation.
- FK: `production_id → v2_1.productions(id)`.
- Status: `READY|INVALID|ARCHIVED`.

### `v2_1.publications`

- Canonical required fields: `id`, `artifact_version_id`, `destination`, `publication_key`, `status`, `result`, `error`, `attempt`, timestamps.
- Defaults: UUID, `PENDING`, JSON objects, attempt and timestamps.
- Unique: `publication_key`; index on artifact/creation and status/update.
- Canonical status: `PENDING|PUBLISHING|PUBLISHED|FAILED`.
- Compatibility preserves legacy `DRAFT|SCHEDULED|CANCELLED|UNKNOWN`. Obsolete `edition_id` and `platform` values remain intact, but their old `NOT NULL` requirement is removed because the certified publication executor does not supply them.
- V2.4 does not insert or execute publications.

### `v2_2.brands`

- Required: `id`, `workspace_id`, `name`, `slug`, `status`, `metadata`, timestamps.
- Defaults: UUID, `ACTIVE`, `{}` and timestamps.
- Unique: `(workspace_id,slug)`; workspace/status index.
- FK: `workspace_id → public.workspaces(id)`.
- Status: `ACTIVE|PAUSED|ARCHIVED`.

### `v2_3.master_review_items`

- Required: workspace/brand/production identity; exact `master_artifact_id`, positive version, storage key and content hash; content type; `PASS` validation; review/validation/provenance/assets JSON; timestamp.
- Defaults: UUID, `video/mp4`, JSON values and timestamp.
- Unique: `(production_id,master_artifact_id,master_storage_key)`; brand/creation index.
- FKs: workspace, `v2_2.brands`, and `v2_1.productions`, all restrictive.
- Trigger proves production, brand and workspace ownership. Review items and decisions are append-only. Approval never publishes.

## Controlled migration

[`20260823_v2_4_legacy_schema_compatibility.sql`](../migrations/20260823_v2_4_legacy_schema_compatibility.sql) is the only legacy bridge. It is idempotent and row-preserving:

- adds missing canonical columns and defaults;
- relaxes only known obsolete `content_variant_id`, `edition_id` and `platform` requirements;
- detects duplicate identities before creating full unique indexes;
- replaces incompatible status checks with explicit compatibility unions;
- removes only helper functions with wrong return signatures so certified migrations recreate them;
- replaces only non-canonical `productions.brand_id` FKs;
- adds new-write-enforced FKs without fabricating semantic data.

Recovery is forward-only: fix any reported duplicate/orphan ownership conflict, then rerun the same migration. Historical migration files remain unchanged from `main`.

## Pre-paid gate

Every dry or paid V2.4 command now performs, in order:

1. full `information_schema`/`pg_catalog` contract inspection;
2. active brand lookup through `v2_2.brands`;
3. a production/job/stage/asset/review write probe inside one transaction followed by `ROLLBACK`;
4. a reversible storage byte round trip outside the immutable artifact namespace;
5. provider configuration and structured input validation.

Only after an immutable operator input artifact is stored does the job durably change `providerRequestState` from `NOT_STARTED` to `MAY_HAVE_STARTED`. The Master orchestrator—and therefore Replicate—can run only after that fenced update.

Failures before this boundary use existing `RETRYING` state and may reuse the same live key. Any recovered run that may have crossed the provider boundary fails closed unless the exact immutable generated video already exists.

## Audit of previous debugging changes

- Correct and retained: explicit paid gate, dry-run default, local database discovery, Provider Gateway path, immutable artifacts, FFmpeg master, exact-master review, idempotent production/job identity.
- Removed as temporary: ad-hoc `normalizeLegacyV21()` and repeated one-error-at-a-time normalization.
- Removed as dangerous: generic removal of `NOT NULL` from unknown columns and compatibility edits embedded in historical migrations.
- Replaced: unconditional helper drops, partial indexes unusable by `ON CONFLICT`, silent `ON CONFLICT DO NOTHING` brand imports, and the legacy `productions_brand_fk`.
