# V2.4 Controlled Live Production

## Purpose

V2.4 provides the smallest explicit operator boundary for one real end-to-end production. It does not add a dashboard button, worker boot path, scheduler, publisher or new production engine.

```text
operator JSON
  -> V2.1 structured validation boundary
  -> brand-scoped PostgreSQL production/job
  -> Provider Gateway
  -> Replicate Wan 2.2 (one video)
  -> immutable media + provenance artifacts
  -> FFmpeg master
  -> existing master quality validation
  -> immutable master
  -> V2.3 exact-master pending review
```

One dedicated, row-preserving compatibility migration upgrades legacy table layouts without modifying certified historical migrations. See [`V2.4-LEGACY-SCHEMA-COMPATIBILITY.md`](V2.4-LEGACY-SCHEMA-COMPATIBILITY.md). Existing V2.1 productions/jobs, ArtifactService storage and V2.3 review tables still represent the complete runtime flow.

## Operator input

Copy [`config/live-production.example.json`](../config/live-production.example.json) outside tracked source and replace its synthetic `brand_id` with an active V2.2 brand UUID. `live_test_key` is the explicit cost/idempotency identity. The input is exactly one scene, one shot and one video asset.

The command validates SCRIPT, SHOT_PLAN and ASSET_PLAN through the existing structured production boundary. Before generation it stores the normalized operator plan as an immutable input artifact.

Safe defaults:

```text
provider: replicate
model: wan-video/wan-2.2-t2v-fast
resolution: 480p
aspect_ratio: 9:16
num_frames: 81
frames_per_second: 16
go_fast: true
expected paid video generations: 1
```

Input values may override the profile. Environment overrides are also supported: `LIVE_VIDEO_RESOLUTION`, `LIVE_VIDEO_ASPECT_RATIO`, `LIVE_VIDEO_NUM_FRAMES`, `LIVE_VIDEO_FPS`, `REPLICATE_VIDEO_MODEL`.

## Required configuration

```text
DATABASE_URL
CONTENT_FACTORY_STORAGE_ROOT
REPLICATE_API_TOKEN
VIDEO_PROVIDER=replicate
LIVE_PRODUCTION_INPUT=/absolute/path/to/operator-input.json
LIVE_PAID_GENERATION=false|true
```

The storage root must already exist and be readable/writable. The token is validated but never printed. Provider health checks and dry-runs do not call Replicate.

## Dry-run

Dry-run checks the complete schema contract, canonical brand FK, active brand ownership, input contracts, Wan profile, provider selection and token. It proves production/job/stage/asset/review writes inside a rolled-back transaction and performs a temporary storage round trip. It creates no durable production, artifact, review or provider request.

```bash
LIVE_PAID_GENERATION=false \
VIDEO_PROVIDER=replicate \
LIVE_PRODUCTION_INPUT=/absolute/path/to/operator-input.json \
npm run live:production
```

Other required values may come from the existing local environment. Dry-run still requires `REPLICATE_API_TOKEN` so it can prove that the live configuration is complete.

## Explicit paid live command

Run only after reviewing a successful dry-run:

```bash
LIVE_PAID_GENERATION=true \
VIDEO_PROVIDER=replicate \
LIVE_PRODUCTION_INPUT=/absolute/path/to/operator-input.json \
npm run live:production
```

For the known local Docker/storage setup, prefer the wrapper so database discovery, compatibility preparation and `CONTENT_FACTORY_STORAGE_ROOT` are supplied consistently:

```bash
LIVE_PAID_GENERATION=true \
VIDEO_PROVIDER=replicate \
LIVE_PRODUCTION_INPUT=/tmp/live-production.json \
npm run live:production:local
```

This is the only paid execution boundary. Nothing invokes it automatically. The default profile requests exactly one Replicate prediction.

At the documented default 480p profile, Replicate currently lists this model at approximately **$0.05 per output video**. The 720p override is currently listed at approximately **$0.10 per output video**. Pricing can change; verify the official model page before enabling the paid gate: <https://replicate.com/wan-video/wan-2.2-t2v-fast>.

Before provider invocation the CLI prints brand, production/live key, provider, model, resolution, aspect ratio, frames, fps, expected generation count and paid-run status.

## Idempotency and cost protection

The deterministic production name and job idempotency key are derived from `live_test_key`. The structured input fingerprint must also match.

- A completed duplicate returns the stored result and makes zero provider calls.
- Concurrent/in-progress, failed or dead-letter runs fail closed.
- An expired run changed to `RETRYING` by existing V2.1 recovery can continue only when the exact immutable video artifact already exists; otherwise the CLI refuses a second prediction.
- Changing structured input under the same key fails with `LIVE_INPUT_CONFLICT`.
- A new paid generation requires a new explicit key.

Replicate's current adapter tracks an in-flight prediction only in process memory and exposes its prediction ID after the call returns. Therefore V2.4 cannot reconcile a process crash while Replicate is still running. It deliberately reports the durable job state and refuses blind resubmission.

## Expected success output

The CLI reports:

```text
productionId
brandId
inputArtifact id/version/storageKey
videoArtifact id/version/storageKey
masterArtifact id/version/storageKey
validationStatus=PASS
reviewStatus=AWAITING_HUMAN_APPROVAL
reviewItemId
provider/model
predictionId
paidGenerationPerformed
publicationTriggered=false
Open Dashboard: http://localhost:3000
```

Storage keys are ArtifactService references, not arbitrary filesystem paths. Tokens and credentials are never output.

## Dashboard verification

After a successful live run:

```bash
npm run dashboard
```

Open `http://localhost:3000`, then Review Queue. The exact immutable master appears pending. Approval remains manual and never publishes.

## Failure behavior

Failed validation does not create a review item. The immutable input/media/master remain in artifact storage and the job error preserves validation evidence and artifact references. Provider or render failures mark the durable live job and production failed. Publication code is never invoked.

## Tests and CI

```bash
npm run test:v2.4:live-production
npm run test:v2.4:legacy-compat:postgres
```

All V2.4 automated tests inject mocks. They assert dry-run behavior, paid gates, brand isolation, malformed input, provider mismatch, idempotency, unresolved in-flight protection, review-ready output, manual approval and zero publication. CI never supplies a real token or calls Replicate.

## Known limitations

- One scene, one shot, one Replicate video, no voice/image generation.
- No CLI auto-retry, New Production UI or Regenerate UI.
- No durable Replicate in-flight reconciliation until the provider boundary persists prediction identity earlier.
- No publication.
- Source video is 480p/16 fps by default; the existing master renderer produces the certified output profile.
- A legacy database can retain unvalidated historical brand rows; the canonical `v2_2.brands` FK is still enforced for every new V2.4 write.
