# V2.10.3 Cross-Shot Continuity Gate

## Purpose

V2.10.3 closes two remaining QUALITY-production gaps on top of V2.10.2: unsafe full-orientation reference normalization and late cross-shot continuity evaluation.

V2.10.2 correctly proved reference bytes and provider-output geometry, but a genuine landscape `PREVIOUS_SHOT_FRAME` could still be converted to a portrait canvas through scale-to-fit plus black padding. Separately, cross-shot continuity evaluation existed but ran only after all source videos had already been generated. That meant a dependent shot could spend a provider call before identity drift in its predecessor was rejected.

## Safe previous-shot reference policy

`PREVIOUS_SHOT_FRAME` now follows a stricter fail-closed policy before an IMAGE_TO_VIDEO provider request:

1. Decode and probe the actual extracted JPEG.
2. If it already matches the canonical aspect ratio, use it unchanged.
3. If its orientation is opposite to the canonical orientation, inspect immutable source-video display/rotation metadata with ffprobe.
4. A deterministic quarter-turn correction is allowed only when source metadata proves a 90° or 270° display rotation. The corrected JPEG is re-probed and must match the canonical aspect ratio.
5. A genuine landscape composition for a portrait production is rejected with `REFERENCE_GEOMETRY_ORIENTATION_INVERSION` before provider execution. It is not converted into a letterboxed portrait reference.
6. Same-orientation aspect mismatch may use proportional scale-to-fit plus padding only within the bounded safe relative-aspect delta. No stretching is permitted.
7. Uploaded references remain verify-only.

No final provider output is cropped to fake compliance.

## Incremental cross-shot continuity gate

QUALITY source acceptance is now sequential:

`shot 1 internal QA → accept shot 1 → shot 2 internal QA → shot 1↔2 continuity gate → accept shot 2 → shot 3 internal QA → accepted chain↔shot 3 continuity gate → master assembly`

A dependent source shot cannot advance the source-asset loop when its continuity gate fails. The existing master-production loop already throws immediately on a failed persisted source evaluation before advancing to the next media asset. V2.10.3 embeds continuity evidence into the source evaluation itself, so a shot-2 continuity block prevents shot-3 provider execution.

The final source-quality aggregation reuses incremental continuity evidence and makes no duplicate continuity evaluator request.

## Continuity dimensions

The semantic continuity critic must return all of these families:

- character identity: face, apparent age, hair, skin and body/build;
- wardrobe;
- environment/layout;
- major props;
- lighting/color language;
- visual/cinematography/rendering style;
- cross-shot realism level;
- acting/motion style and planned emotional progression.

Planned framing, camera distance, angle, lens, blocking, or emotional progression changes are allowed. They must not by themselves be classified as character drift.

A within-shot `HUMAN_VISUAL_INTEGRITY` pass never proves cross-shot identity. Serious identity drift is separately represented by `CHARACTER_IDENTITY_DRIFT` and blocks QUALITY acceptance.

## Typed continuity reasons

V2.10.3 adds explicit reasons including:

- `CONTINUITY_PREDECESSOR_EVIDENCE_MISSING`
- `CHARACTER_IDENTITY_DRIFT`
- `WARDROBE_CONTINUITY_DRIFT`
- `ENVIRONMENT_CONTINUITY_DRIFT`
- `PROP_CONTINUITY_DRIFT`
- `LIGHTING_COLOR_CONTINUITY_DRIFT`
- `VISUAL_STYLE_CONTINUITY_DRIFT`
- `CROSS_SHOT_REALISM_DRIFT`
- `ACTING_STYLE_CONTINUITY_DRIFT`

`CHARACTER_IDENTITY_DRIFT` and missing predecessor evidence are hard failures.

## Durable evidence and provenance

Continuity evidence records:

- evaluator provider/model/version;
- external-call count and request identity where available;
- compared shot IDs;
- compared asset IDs;
- compared artifact IDs, versions, and content hashes;
- sampled frame hashes and timestamps;
- per-family PASS/WARN/FAIL checks;
- incremental gate position and current shot identity.

Accepted replacement lookup supports both `SOURCE_GEOMETRY` and future `SOURCE_CONTINUITY` lineage while preserving historical failed artifacts.

## Cost accounting

Continuity is counted independently from semantic source evaluation.

For N accepted/generated video shots in an operational semantic QUALITY lane:

- source semantic evaluations: N;
- continuity evaluations: max(0, N - 1);
- final semantic evaluations: only when the existing final-master policy requires them.

A deterministic hard source block still skips paid semantic evaluation. Because the shot never becomes internally acceptable, the cross-shot continuity gate is also skipped.

Early continuity failures remain visible in durable external-call accounting even though the final aggregate continuity object has not yet been constructed.

## Existing Attune recovery

For the current failed Attune production:

- shot 1 remains immutable and reusable;
- failed landscape shot-2 v1 remains immutable evidence;
- geometry recovery may create shot-2 v2 with a new durable identity;
- on `CONTINUE SAME EXECUTION`, shot-2 v2 is internally validated and then cross-shot continuity-gated against accepted shot 1;
- shot 3 cannot execute unless shot-2 v2 passes the required continuity gate;
- if shot-2 v2 fails continuity, the production blocks before shot 3 and requires an explicit operator regeneration decision. There is no automatic infinite paid loop.

## Safety

- `WRONG_ORIENTATION` remains a hard failure.
- No existing validation is weakened.
- Historical artifacts are not modified or deleted.
- No final-output crop is used as repair.
- Reference validation and rotation inspection make zero provider calls.
- Tests use synthetic/mocked evaluators; no live provider execution is required.
- Human review remains required and auto-publish remains disabled.
