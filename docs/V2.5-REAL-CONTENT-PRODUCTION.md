# Content Factory V2.5 — real short-form production

V2.5 extends the certified V2.4 live path into a reusable operator-driven pipeline:

`operator input → deterministic shot/asset plan → durable media executions → FFmpeg master → media validation → human review`

It does not add an automatic publication path. A technical validation PASS only makes the exact immutable master eligible for Review Queue; it never grants publication permission.

## Operator contract

The external JSON contract represents brand and production identity, objective, target platform/duration/aspect ratio, hook, core message, creative concept, CTA, scenes, variable-count shots, voiceover, continuity, visual style, audio/music ambience intent, captions intent, and a fail-closed publication policy.

Each shot supplies its own duration and video generation profile. The planner derives one primary video asset per requested shot; it does not force a fixed number of shots. Voiceover is a separate immutable voice asset spanning the requested shots.

The initial real operator input is `config/productions/attune-dont-guess-tune-in.json`. It is data, not application logic. The same schema can be used by Attune, NOW, LuxuryItaly.net, or a future brand with an explicit canonical `brand_id`.

## Safe dry-run

```bash
LIVE_PAID_GENERATION=false \
REAL_PRODUCTION_INPUT=config/productions/attune-dont-guess-tune-in.json \
VIDEO_PROVIDER=replicate AUDIO_PROVIDER=openai-media \
npm run real:production:local
```

The local wrapper discovers the same `content_os` database/storage used by `live:production:local`, applies ordered local migrations, and then runs the V2.5 pre-paid plan. No provider credential is required for dry-run.

Dry-run performs rollback-only production/job/media writes and claims against the real constraints. It stops before provider invocation and reports the canonical brand/key, duration, video/audio calls and models, FFmpeg assembly mode, existing idempotency state, publication policy, and cost as unknown when current pricing is not encoded in the engine.

Invariant: `dryRunProviderCalls = 0`.

## Explicit paid boundary

Paid execution remains a separate, explicit operator action. Do not run this during development certification:

```bash
LIVE_PAID_GENERATION=true \
REAL_PRODUCTION_INPUT=/absolute/path/to/approved-input.json \
VIDEO_PROVIDER=replicate \
AUDIO_PROVIDER=openai-media \
npm run real:production:local
```

Only paid mode requires the provider credentials for assets in the plan. The local default remains false.

## Per-asset durability and recovery

Migration `20260823_v2_5_durable_media_executions.sql` adds a canonical workspace/brand/production-scoped execution record per media asset. Identity fields and the input fingerprint are immutable.

The lifecycle is `NOT_STARTED → RUNNING → MAY_HAVE_STARTED → SUCCEEDED`.

Pre-provider failures become `RETRYABLE`. An error after the provider boundary becomes `NEEDS_RECONCILIATION`; it is never reset silently. Replicate prediction IDs are persisted immediately after prediction creation. A rerun polls/downloads that existing prediction instead of creating a new one. If neither an immutable artifact nor a recoverable request ID exists, execution fails closed with `MEDIA_PROVIDER_STATE_UNRESOLVED`.

The deterministic artifact key also closes the crash window after provider output: if bytes were persisted but the database completion update was interrupted, the next run validates and adopts the exact immutable artifact without another provider call.

## Media and review validation

Every generated video/voice asset is inspected with `ffprobe` before it is accepted. The master is assembled from ordered video segments and voice/audio with the existing FFmpeg renderer, then checked for non-empty readable media, video and audio streams, dimensions, frame rate, and duration tolerance.

The Review Queue serves media by validated brand-scoped artifact identity with the correct MIME type. It displays the master preview, production/review/publication state, duration/codecs, validation evidence, providers/models, generated assets, and Approve/Reject controls. Approval records a human decision only; it does not publish.
