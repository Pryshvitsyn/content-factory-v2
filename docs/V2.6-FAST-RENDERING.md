# Content Factory V2.6 — FAST rendering

V2.6 adds a replaceable FAST renderer lane without changing the certified V2.5 QUALITY implementation.

```text
Production Input
      ↓
Renderer Router
   ↙       ↘
FAST       QUALITY
 ↓            ↓
MPT       V2.5 Replicate/OpenAI/FFmpeg
   ↘          ↙
    ArtifactService
          ↓
      ffprobe validation
          ↓
       Review Queue
```

Content Factory continues to own production identity, workspace/brand scope, durable state, idempotency, artifacts, validation, review, and publication permission. MoneyPrinterTurbo (MPT) owns only one external rendering task and remains replaceable through the renderer registry.

## Pinned upstream contract

- Project: [harry0703/MoneyPrinterTurbo](https://github.com/harry0703/MoneyPrinterTurbo)
- License: MIT
- Release: `v1.3.3`
- Release commit: `b4218dd`
- Image: `ghcr.io/harry0703/moneyprinterturbo:v1.3.3`
- Manifest digest: `sha256:436e0aefc81cda8a5952a2bc3a1139385498721114df59e5818d1ba851763001`

The adapter is based on the release API, not its Python internals:

- submit: `POST /api/v1/videos`;
- task ID: response `data.task_id`;
- poll/recover: `GET /api/v1/tasks/{task_id}`;
- task states: `-1` failed, `1` complete, `4` processing;
- output: the first safe URL from `videos`, then `combined_videos`;
- health: `GET /openapi.json` (never starts a render).

The adapter accepts only same-origin `/tasks/`, `/api/v1/download/`, or `/api/v1/stream/` output URLs, rejects traversal/cross-origin paths, bounds download size, and copies bytes into Content Factory storage. MPT paths never become Review Queue ownership.

The pinned upstream service also contains an optional Upload-Post integration. Content Factory requires `MPT_AUTO_PUBLISH_DISABLED=true`, the companion refuses startup unless both `app.upload_post_enabled` and `app.upload_post_auto_upload` are false, and the adapter rejects any task response containing `cross_post_state`. This keeps publication fail-closed at both the operator and service boundary.

Important security limitation: the `v1.3.3` API router does not enforce its API-key dependency. The companion service therefore binds only to `127.0.0.1`. `MPT_API_KEY` is supported as a forward-compatible optional request header but is not treated as protection for this pinned release. Do not expose port 8080 publicly.

## Production input

V2.5 JSON remains backward compatible and defaults to `QUALITY`. A V2.6 FAST input adds only:

```json
{
  "schema_version": "2.6",
  "render_mode": "FAST",
  "fast_render": {
    "renderer": "moneyprinterturbo",
    "media_source": "pexels",
    "captions": true,
    "music": true,
    "provider_options": {}
  }
}
```

Provider-specific options are whitelisted under `fast_render.provider_options`; they are not promoted into the canonical production contract. The example is `config/productions/attune-fast-example.json`. It is brand data, not Attune-specific engine logic.

MPT `subtitle_enabled` creates captions inside its rendered video. Content Factory records the intent and validates the resulting media container, but does not currently OCR the output to prove subtitle text or timing.

## Configuration

Common required variables:

| Variable | Meaning |
| --- | --- |
| `DATABASE_URL` | Canonical PostgreSQL database. The local wrapper discovers this when possible. |
| `CONTENT_FACTORY_STORAGE_ROOT` | Content Factory-owned immutable artifact storage. |
| `REAL_PRODUCTION_INPUT` | External production JSON path. |
| `LIVE_PAID_GENERATION` | Must be exactly `false` for dry-run or `true` for an operator-approved execution. |
| `RENDER_MODE` | `FAST` or `QUALITY`; must match the input. |

FAST variables:

| Variable | Default / rule |
| --- | --- |
| `FAST_RENDERER` | `moneyprinterturbo`; must match the input registry key. |
| `MPT_ENABLED` | Must be explicitly `true` or `false`. Live FAST requires `true`. |
| `MPT_BASE_URL` | Required HTTP(S) origin, normally `http://127.0.0.1:8080`. |
| `MPT_VERSION` | `v1.3.3`; recorded in execution and artifact provenance. |
| `MPT_API_KEY` | Optional forward-compatible header; not effective authentication in pinned v1.3.3. Never expose it to the browser. |
| `MPT_REQUEST_TIMEOUT_MS` | Per-HTTP-request timeout; default `15000`. |
| `MPT_POLL_INTERVAL_MS` | Task poll interval; default `2000`. |
| `MPT_MAX_WAIT_MS` | Total polling window; default `900000`. |
| `MPT_MAX_OUTPUT_BYTES` | Download ceiling; default `268435456` (256 MiB). |
| `MPT_HEALTHCHECK` | Set `false` to report `NOT_PROBED`; default probes OpenAPI only. |
| `MPT_AUTO_PUBLISH_DISABLED` | Must be exactly `true`; operator attestation that both upstream Upload-Post flags are false. |

Companion Compose variables:

| Variable | Meaning |
| --- | --- |
| `MPT_CONFIG_FILE` | Absolute path to an uncommitted upstream `config.toml`. |
| `MPT_HOST_PORT` | Localhost host port, default `8080`. |

Stock, LLM, speech, and music credentials belong only in the external MPT configuration/environment. They must not be committed or returned by the Content Factory dashboard. External services can incur cost, so V2.6 reports cost as `unknown` unless deterministic evidence exists.

## Local companion startup

Prepare an external MPT `config.toml` using the pinned upstream release instructions. Keep that file outside Git and ensure `[app]` contains `upload_post_enabled = false` and `upload_post_auto_upload = false`. The companion command validates both values before starting the API. Then run:

```bash
export MPT_CONFIG_FILE=/absolute/path/to/moneyprinterturbo/config.toml
docker compose -f deploy/moneyprinterturbo/docker-compose.yml pull
docker compose -f deploy/moneyprinterturbo/docker-compose.yml up -d
curl --fail http://127.0.0.1:8080/openapi.json >/dev/null
```

The compose file starts only the API service, binds to localhost, uses an isolated named storage volume, and does not alter Content Factory PostgreSQL/n8n services. No Redis service is required by the pinned API compose path. The image contains Python and FFmpeg; stock acquisition and some voice/subtitle features require network access from the companion.

Upstream does not publish a fixed resource minimum. CPU, RAM, disk, and run time depend on duration, source media, subtitle transcription, and codec work. Capacity and Apple Silicon behavior are not certified by this repository; monitor the first operator-controlled job and retain enough disk for MPT temporary media plus the final Content Factory artifact.

Stop the companion without deleting its volume:

```bash
docker compose -f deploy/moneyprinterturbo/docker-compose.yml down
```

## Migration

`migrations/20260824_v2_6_fast_render_executions.sql` creates `v2_6.fast_render_executions`. It is ordered/repeatable and enforces immutable workspace + brand + production + mode + renderer + input identity.

Forward-only recovery is intentional. Do not reset or delete ambiguous rows. A durable MPT task ID is polled on retry; an execution that may have crossed the boundary without a task ID fails closed for manual reconciliation.

Lifecycle:

```text
NOT_STARTED → RUNNING → MAY_HAVE_STARTED → REQUEST_ACCEPTED → PROCESSING → SUCCEEDED
                 │              │                  │
                 └─ RETRYABLE   └────────── NEEDS_RECONCILIATION
                                      ├── FAILED
                                      └── VALIDATION_FAILED
```

The task ID is persisted immediately after the submit response. After successful download, ffprobe validation must pass before immutable artifact adoption and Review Queue registration. A valid cached artifact is revalidated and reused without another MPT POST.

## Safe dry-run

Start the companion if an `AVAILABLE` health result is desired. The dry-run sends only `GET /openapi.json`; it sends no `POST /api/v1/videos` and creates no persistent production/render row:

```bash
LIVE_PAID_GENERATION=false \
REAL_PRODUCTION_INPUT=config/productions/attune-fast-example.json \
RENDER_MODE=FAST \
FAST_RENDERER=moneyprinterturbo \
MPT_ENABLED=true \
MPT_AUTO_PUBLISH_DISABLED=true \
MPT_BASE_URL=http://127.0.0.1:8080 \
npm run real:production:local
```

The plan reports `renderMode: FAST`, the renderer/version, availability, target output, cost status, `providerExecutions: 0`, `dryRunRendererExecutions: 0`, and schema readiness.

## Operator-controlled real FAST generation

This command is intentionally not run by CI, tests, migrations, dashboard startup, or documentation verification. Review the input, MPT configuration, stock/TTS cost exposure, storage capacity, and dry-run first:

```bash
LIVE_PAID_GENERATION=true \
REAL_PRODUCTION_INPUT=config/productions/attune-fast-example.json \
RENDER_MODE=FAST \
FAST_RENDERER=moneyprinterturbo \
MPT_ENABLED=true \
MPT_AUTO_PUBLISH_DISABLED=true \
MPT_BASE_URL=http://127.0.0.1:8080 \
npm run real:production:local
```

Successful execution ends at `AWAITING_HUMAN_APPROVAL`. Approval records the exact-master decision and never publishes.

## Current limitations

- Only vertical `9:16`, 1080×1920 FAST masters are certified.
- MPT v1.3.3 has no explicit target-duration request field; output duration follows generated speech/media. The example copy is tuned for about 10 seconds, and Content Factory rejects output outside its ±1.5-second validation tolerance.
- MPT face/character continuity is not guaranteed; FAST is intended for stock-driven short videos.
- Content Factory validates media structure, dimensions, duration, and required audio, but not visual semantics, caption OCR, loudness, or stock license suitability.
- MPT service availability in the dashboard is configuration-only (`CONFIGURED_NOT_PROBED`); the CLI dry-run performs the lightweight live health check.
- MPT internal stock/TTS/music requests are opaque to Content Factory. Cost therefore remains `unknown`.
- The first real MPT render remains an explicit local operator action and is not certified by mocked tests.
