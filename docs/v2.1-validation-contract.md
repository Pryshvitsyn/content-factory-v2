# V2.1 Validation Contract

## Purpose

Define the provider-neutral validation boundary between immutable artifact versions and downstream publication.

## Canonical flow

Artifact Version → Validation Engine → Validation Result → stage gate

## Validation Result

Each validation result is associated with an immutable artifact version and records:

- `validation_type`: stable validation category;
- `status`: `PASS`, `WARN`, or `FAIL`;
- `score`: optional normalized numeric score;
- `findings`: structured machine-readable findings;
- creation timestamp and provenance through the referenced artifact version.

## Rules

1. Validation never mutates an artifact version.
2. Validation targets an immutable artifact version, never a mutable logical artifact identity.
3. Multiple validation results may exist for the same artifact version.
4. A `FAIL` result blocks downstream publication for that artifact version.
5. `WARN` is non-blocking unless a stage-specific policy explicitly promotes it to blocking.
6. `PASS` is non-blocking.
7. Validation is provider-neutral; provider/model details remain provenance on the artifact version or stage attempt.
8. Findings must be structured data, not an opaque free-form status string.
9. Validation execution must be idempotent for the same artifact version, validation type, and validation policy identity.
10. The validation layer must not modify job claim, lease, retry, or concurrency semantics.

## Initial validation categories

- `schema`: structural/schema compliance;
- `content`: content-level policy/quality checks;
- `technical`: technical/media constraints;
- `continuity`: continuity and required-reference checks;
- `readiness`: aggregate downstream publication readiness.

## Publication gate

`PUBLISH` may proceed only when all blocking validations for the target artifact version resolve to `PASS`.

A missing required validation is not equivalent to `PASS`.

## Scope of the next implementation PR

The implementation should add only the canonical validation contract and deterministic tests for:

- PASS;
- WARN;
- FAIL;
- immutable artifact-version targeting;
- blocking publication on FAIL;
- missing required validation does not pass the gate;
- idempotent validation identity.

No provider integration, worker claim logic, lease/recovery logic, or concurrency behavior is changed by this layer.
