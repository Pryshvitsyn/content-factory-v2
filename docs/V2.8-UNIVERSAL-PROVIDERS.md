# Content Factory V2.8 — Universal Provider Layer

V2.8 separates Factory production ownership from external generation protocols. Brand context, creative planning, canonical requests, explicit routing, durable execution, artifacts, FFmpeg assembly, validation, review, and publication permission remain Factory responsibilities. Provider adapters own only request translation, external execution, recovery, and output normalization.

## Routing contract

The normal QUALITY operator route has three fields: `provider`, `model`, and `profile`. `ProviderCatalog` resolves those values to a provider type, vendor, model/version, capability, adapter family, and model-aware settings before any external call. The resolved selection is embedded in the canonical raw input, production metadata/job payload, every video asset's generation requirements, and immutable media provenance.

`AUTO` is intentionally rejected. An explicit provider selection never falls back to another provider or profile. The fail-closed codes are `SELECTED_PROVIDER_UNAVAILABLE`, `SELECTED_MODEL_UNAVAILABLE`, `SELECTED_PROFILE_UNAVAILABLE`, `CAPABILITY_UNSUPPORTED`, and `CREDENTIALS_MISSING`, plus constraint-specific duration, resolution, and aspect-ratio errors.

Credential presence yields `CONFIGURED_NOT_PROBED`, not `READY`. `READY` can only be supplied by a non-generating health probe or an explicit operational override. Catalog responses contain booleans/status only and never secret values.

## Canonical media request

`src/v2.8/canonical-media-request.js` owns the provider-neutral contract: capability, prompts, duration, ratio, resolution, reference groups, audio intent, camera, continuity, seed, provider selection, and resolved settings. A request containing references cannot remain `TEXT_TO_VIDEO`; it must use a compatible image/reference/video capability. Adapters do not receive references the selected model cannot support.

The normalized capabilities are:

- `TEXT_TO_VIDEO`, `IMAGE_TO_VIDEO`, `REFERENCE_TO_VIDEO`, `VIDEO_TO_VIDEO`
- `TEXT_TO_IMAGE`, `IMAGE_TO_IMAGE`
- `SPEECH`, `MUSIC`, `FAST_RENDER`

## Provider families

The catalog distinguishes aggregators (`replicate`, `fal`) from direct providers (`runway`, `google`, `luma`, `openai`) and the local FAST renderer (`moneyprinterturbo`). Models separately record `provider`, `vendor`, and `modelId`.

Verified protocol implementations are fixed in source code and tested with synthetic HTTP responses:

- Replicate: existing certified Wan adapter; the official Predictions API remains the aggregator protocol. Additional Replicate families are cataloged as experimental until their exact input schema is certified. [Replicate HTTP API](https://replicate.com/docs/reference/http/)
- fal.ai: persistent queue submit/status/result flow with documented Seedance 2.0 text/reference endpoints. [fal async inference](https://fal.ai/docs/documentation/model-apis/inference/queue), [Seedance 2.0 API](https://fal.ai/models/bytedance/seedance-2.0/text-to-video/api)
- Runway: `POST /v1/text_to_video`, `GET /v1/tasks/{id}`, `X-Runway-Version: 2024-11-06`, and Gen-4.5. [Runway API](https://docs.dev.runwayml.com/api/)
- Google: Veo 3.1 `predictLongRunning`, operation polling, authenticated file download, portrait output, and eight-second generation. [Google Veo 3.1](https://ai.google.dev/gemini-api/docs/veo)
- Luma: Dream Machine generation create/status flow for Ray 2. [Luma generation API](https://docs.lumalabs.ai/reference/creategeneration)
- OpenAI speech and MoneyPrinterTurbo FAST keep their existing certified adapters.

All real-provider tests are manual acceptance boundaries. Automated tests make zero real or paid calls.

## Profiles

Standard names are `ECONOMY`, `STANDARD`, and `PREMIUM`, but availability and settings belong to each model. A profile may resolve resolution, supported duration, quality/fast flags, audio behavior, prompt optimization, reference behavior, and fixed adapter settings. A missing profile fails closed; profiles are never silently downgraded.

Exact prices are not inferred from provider marketing pages. Until a pricing rule is separately encoded and certified, preflight reports `Cost: UNKNOWN`.

## Adding a model to an existing aggregator

The Providers page can add a compatible fal or Replicate model in a canonical brand workspace with:

1. Provider
2. Model ID
3. Safe capability/profile preset
4. Optional display name

The additive `v2_8.provider_models` table stores only routing metadata—never credentials. Its provider/model/adapter/capability/preset identity is immutable and workspace scoped. Dashboard-created entries start `EXPERIMENTAL`; `V28_ALLOW_EXPERIMENTAL_MODELS=true` is an explicit operator gate, not a silent activation.

Presets are validated enumerations. They cannot supply URLs, headers, JavaScript, templates, or request/response mappings. A newly registered model is configuration-only only when its provider adapter family and exact input schema are compatible and certified.

## Adding a new provider protocol

A genuinely different API requires:

1. One isolated adapter/protocol mapping implementing support, validation, estimate, submit, status, recover, download, and normalized result behavior.
2. One catalog provider/model registration.
3. Mock contract, negative, routing, recovery, and provenance tests.

No changes should be required in the creative planner, command boundary, durable executor, ArtifactService, FFmpeg master assembly, review queue, publication policy, or normal Dashboard workflow.

`AsyncMediaProviderAdapter` is deliberately not an arbitrary HTTP executor. Only reviewed protocol objects compiled into the server can map URLs and payloads. Dashboard/database configuration cannot execute code or choose arbitrary endpoints.

## Environment and safety

Credential variable names are `REPLICATE_API_TOKEN`, `FAL_KEY`, `RUNWAYML_API_SECRET`, `GOOGLE_API_KEY` (with `GEMINI_API_KEY` accepted for the Gemini API), `LUMA_API_KEY`, and `OPENAI_API_KEY`. Values stay in the server environment. `.env.example` contains placeholders only.

Preflight resolves provider, vendor, model, profile, capability, resolution, generation counts, external request count, cost status, and configuration status while executing zero providers. Human approval remains required and auto-publication remains disabled.

The migration is additive and forward-only. Recovery is to disable V2.8 routes/adapters while preserving catalog registrations, historical productions, durable executions, provenance, and artifacts.
