# V2.9.1 Real Semantic Visual Quality Evaluation

V2.9.1 connects the provider-neutral V2.9 `SemanticVisualEvaluatorAdapter` contract to an OpenAI vision-capable model. `VisualQualityEvaluator` remains unaware of OpenAI, and the video generator remains independent from the critic.

## Configuration and paid boundary

All configuration is server-side. The model has no silent default.

```text
OPENAI_API_KEY=...
SEMANTIC_VISUAL_ENABLED=true
SEMANTIC_VISUAL_PROVIDER=openai
SEMANTIC_VISUAL_MODEL=<explicit vision-capable OpenAI model>
LIVE_PAID_VISUAL_EVALUATION=true
SEMANTIC_VISUAL_TIMEOUT_MS=30000
SEMANTIC_VISUAL_MAX_RETRIES=1
```

`SEMANTIC_VISUAL_ENABLED`, provider, model, API key presence, paid gate, timeout, and retry settings are validated locally. Preflight sends no request to OpenAI. STANDARD and PREMIUM are blocked before video or speech generation when the evaluator is disabled, invalid, unsupported, missing credentials/model, or has a closed paid gate. ECONOMY remains available as a visible draft WARN with no fabricated semantic PASS.

`LIVE_PAID_GENERATION=true` authorizes generation; it does not authorize the critic. `LIVE_PAID_VISUAL_EVALUATION=true` is independently required before evaluator HTTP requests. Tests and normal preflight use mocks or local validation and make zero real provider calls.

## API and structured output

The adapter uses `POST /v1/responses` with ordered JPEG frames as base64 `input_image` content, timestamps and ratios as text context, `store: false`, and a strict `text.format` JSON schema. The response must contain PASS/WARN/FAIL checks with a registered reason code, quality class, confidence, concise visible-evidence reason, and frame ratios/timestamps. Local validation recomputes the weakest-link aggregate; malformed JSON, invalid schema, aggregate mismatch, refusal, timeout, authentication, rate limit, HTTP, and network failures all become explicit FAIL evidence. They can never become PASS.

The critic evaluates:

- coherent single composition and unexpected split screens, diptychs, triptychs, collages, contact sheets, picture-in-picture, panels, and borders;
- generated text-like artifacts, pseudo-text, subtitles, captions, signage, logos, watermarks, and UI without requiring exact transcription;
- severe face, anatomy, limb, hand, duplication, and identity defects;
- subject, environment, action, framing, emotion, style, negative-intent, realism, and brand/prohibited-element compliance;
- ordered-frame identity drift, duplication, disappearance, object mutation, environment mutation, and shot incoherence;
- multi-shot character, wardrobe, hair, location, prop, light/color, and overall visual-identity continuity.

Explicitly requested panels, text, logos, UI, phones, or stylization are not prohibited by default. The critic is instructed to judge only visible evidence, not invent certainty, and use WARN for ambiguous/minor defects.

## Evaluation and call policy

Planned evaluator operations are derived from the actual video count and tier:

| Tier | Source semantic | Continuity | Final semantic |
| --- | --- | --- | --- |
| ECONOMY | Optional when configured; otherwise visible WARN | One call only for multiple shots when configured | Only for an explicitly visually transformed master |
| STANDARD | One per source video | One call for multiple shots | Only when the master adds visual transformations such as rendered text/layout |
| PREMIUM | One per source video | One call for multiple shots | One final-master call |

Scaling, padding, deterministic assembly, and audio muxing alone reuse source semantic evidence for STANDARD. The final master still receives deterministic and temporal checks, with semantic marked `SEMANTIC_VISUAL_EVALUATION_NOT_REQUIRED` and `externalCalls: 0`. A one-shot production records `CONTINUITY_NOT_APPLICABLE` with zero continuity calls.

Preflight reports video generations, speech generations, source/final semantic evaluations, continuity evaluations, evaluator provider/model/status, execution classes, and total expected calls. Conditional infrastructure retries are bounded separately (`0..2`; default `1`) and recorded as actual HTTP attempts. Retryable conditions are 429, selected 5xx responses, timeouts, and network failures. An evaluator failure never triggers video regeneration.

Safe immutable evidence includes provider, model, evaluator version, sampled-frame hashes/timestamps, structured checks, confidence, request ID, numeric usage metadata, attempts, and `knownCost: UNKNOWN`. API keys, authorization headers, and raw provider internals are not persisted or sent to the Dashboard.

## V2.9.2 required-family contract and recovery

The SOURCE structured-output schema uses a fixed `checks` object. Its required properties are `composition`,
`generatedText`, `humanIntegrity`, `creativeCompliance`, `realism`, `brandSafety`, and
`temporalConsistency`; each property accepts only reason codes belonging to that family. Continuity retains the
same fixed-object treatment for `visualIdentity`, `wardrobe`, `location`, `props`, and `lightingColor`. The adapter
normalizes these objects back to the existing internal check array. Missing, refused, incomplete, or inconsistent
output still fails closed; no family is synthesized as PASS.

An isolated evaluator infrastructure/output-contract failure can expose `RETRY SEMANTIC EVALUATION`. Eligibility
requires prior deterministic and temporal PASS evidence, a retryable semantic failure only, and immutable sampled
frames whose bytes still match their recorded hashes. The command loads succeeded durable media without calling a
generation provider, fixes evaluator HTTP retries to zero for an exact one-request ceiling, persists a new
`v2_9.semantic_evaluation_attempts` record with the source artifact and prior evidence, and preserves the previous
failure. Its explicit call budget is video generation `0`, speech generation `0`, semantic evaluation `1`. PASS may
continue cached master assembly; FAIL remains blocked. A visible content defect is not eligible for this recovery.
