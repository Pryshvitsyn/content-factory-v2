# V2.10.2 Reference Geometry & Source Recovery

## Root cause

V2.10 materialized the final representative frame of a succeeded shot for `PREVIOUS_SHOT_FRAME`, but it did not decode and prove the geometry of the resulting JPEG. Wan 3 correctly receives either `image` or `aspect_ratio`: when `image` is present, `alibaba/wan-3` inherits framing from that image and does not use `aspect_ratio` to override it. A 9:16 production could therefore send an incorrectly materialized landscape frame and spend a provider generation that returned landscape media.

## Reference geometry invariant

Every image-to-video request now has this fail-closed chain:

`canonical aspect ratio → immutable source artifact → extracted/uploaded bytes → decoded dimensions → content hash → canonical media request → provider input`

The persisted reference evidence records the decoded width, height, ratio, orientation, expected ratio, source artifact identity/version/hash, reference hash, and normalization policy/version. Wan 3 accepts a first frame only when the canonical request says `IMAGE_TO_VIDEO`, the locally recorded dimensions match the canonical ratio, and the hash of the supplied data URI matches the locally verified reference hash.

### Normalization policy

Only `PREVIOUS_SHOT_FRAME` is normalized automatically. V2.10.2 uses FFmpeg to proportionally scale the entire extracted frame to fit the canonical dimensions, then pads to the target canvas and sets square pixels. It never stretches or crops the source. The result is probed again. Any decode, transformation, or verification failure raises `REFERENCE_GEOMETRY_MISMATCH` before the provider boundary.

`UPLOADED_REFERENCE` is verify-only. A mismatched upload is rejected unless a future explicit operator policy authorizes a transformation; V2.10.2 does not silently crop it.

## Wan 3 provider behavior

Text-to-video continues to send `aspect_ratio`. Image-to-video sends `image` and deliberately omits `aspect_ratio`, because framing is inherited from the verified first frame. Provider provenance records the capability, canonical ratio, resolved settings, verified reference geometry, and whether framing came from `VERIFIED_FIRST_FRAME` or `ASPECT_RATIO_PARAMETER`.

## Provider output invariant

Generated video is probed before it is adopted as usable media. If its decoded ratio conflicts with the canonical request, the execution fails with `PROVIDER_OUTPUT_GEOMETRY_MISMATCH`. Error evidence includes provider, model, asset, requested ratio, actual dimensions/ratio, reference dimensions/hash, provider request ID, and the immutable rejected-output artifact. The rejected bytes remain evidence and cannot enter master assembly.

## Bounded recovery and cost behavior

`WRONG_ORIENTATION` and `PROVIDER_OUTPUT_GEOMETRY_MISMATCH` are objective media failures. They are classified as `REGENERATE_SHOT`, never as `RE_EVALUATE_EXISTING_ASSET`. The operator sees a new paid-call preflight and must explicitly confirm it.

The automatic geometry route permits exactly one replacement generation for a source asset. A partial unique database index enforces that bound under concurrency. The replacement receives a new asset ID, canonical fingerprint, durable media execution, idempotency key, and provider request identity. A failed replacement is terminal for this route; another attempt requires explicit future operator escalation. There is no retry loop.

The maximum recovery preflight is one video call plus one semantic source evaluation. If deterministic validation of the replacement produces a hard technical block, the semantic call is skipped and durable evidence records `NOT_EVALUATED_DUE_TO_DETERMINISTIC_BLOCK` with zero semantic external calls.

## Artifact lineage and same-production continuation

The failed source remains immutable. A successful recovery records:

- source and replacement asset IDs;
- logical lineage and artifact versions;
- superseded artifact identity when available;
- retry reason and automatic-attempt number;
- provider/model/capability/settings/request ID/seed;
- canonical and actual geometry;
- reference evidence and replacement quality evidence.

Only the exact failed durable job is moved to `RETRYING`. On continuation, the reference-aware executor substitutes the successful replacement for the original failed asset. Good earlier video and audio are reused. A later `PREVIOUS_SHOT_FRAME` lookup resolves the latest successful replacement, so shot 3 references shot 2's successful replacement rather than its failed historical bytes. Normal source generation then continues and master assembly remains subject to all existing quality gates and human approval.

## Dashboard recovery

For an objective geometry failure, use **REGENERATE FAILED SHOT · 1 VIDEO** in the V2.10.2 Safe Recovery panel. Review the dimensions, expected ratio, maximum external calls, reuse statement, and unknown/known cost, then explicitly confirm. After the replacement succeeds, use **CONTINUE SAME EXECUTION**. Do not use semantic re-evaluation for the old landscape bytes and do not create a new production.

The Shot Inspector and immutable revision history expose the recovered source geometry, provider request, reference lineage, artifact/supersession information, and retry reason without exposing provider credentials.

## Safety boundaries

- No validation status was weakened; `WRONG_ORIENTATION` remains a hard failure.
- No historical media or quality artifact is overwritten or deleted.
- No final-output crop is used as a repair.
- No provider call occurs during reference validation or normalization.
- Tests use mocked providers and perform zero real external provider calls.
- Human approval and `autoPublish: false` remain unchanged.
